# launch-checklist.md — <piece title>

> Copy this file per launch. The agent maintains it; nothing ships with an unchecked gate. Add gates when something bites you — that's how the checklist earns its keep.

## Gate A — the piece is finished
- [ ] Watched / read the final export start to finish, hands off, once
- [ ] Captions/subtitles built against the FINAL export, not a draft — and proofread (names, product terms)
- [ ] Chapters / sections rebuilt from the final cut
- [ ] The last 15–20 seconds are clean (end screens / CTAs need the room)

## Gate B — packaging
- [ ] Title locked — and if the platform supports A/B testing, it's running **from minute one** (packaging gets graded in roughly the first 24 hours; a test that starts on day 2 spent its audition already)
- [ ] Thumbnail/cover readable at the size the feed actually shows it (~168px wide). If the words don't survive that, it fails.
- [ ] Description written for the first two lines (that's all most surfaces show)

## Gate C — the upload screen
- [ ] Publish now beats scheduled premiere unless you have an audience to gather
- [ ] Links present and tested (cross-promotion, mailing list, companion posts)
- [ ] Pinned comment ready (one question that invites replies)

## After launch — write it back
- [ ] Record checkpoints in `launch-tracking.md` (~13h, ~24h, ~48h, 7d): what the screen says, then what it means — separately
- [ ] One lesson extracted into the project's `context.md`, so the next launch starts smarter
