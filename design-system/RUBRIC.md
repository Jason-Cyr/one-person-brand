# RUBRIC.md — the taste file

> This file is how the AI borrows the human's taste. It starts as a template; it becomes real the first time the human rates a render honestly and their complaints get written in. **Ship bar: nothing goes out below 8/10 against this rubric.** Score every asset before it ships — ideally in a fresh agent session that sees only the render, not the effort behind it.

## How to score

10 points, one per line below. An asset that fails a line loses the point — no halves, no "almost." Write the score and the failing lines into the asset's eval notes.

## The ten lines (edit these as the human's taste reveals itself)

1. **Feed-size test** — at the size the audience actually sees it (~380px post / ~168px thumbnail), the main words are readable and the point is clear.
2. **One idea** — the asset says one thing. A viewer can repeat it back after 3 seconds.
3. **Hierarchy** — exactly one element dominates. If everything is loud, it fails.
4. **On-token** — only system colors and typefaces; no invented sizes between scale steps.
5. **Breathing room** — generous empty space is present and deliberate; nothing crowds an edge or collides.
6. **Accent discipline** — the accent color marks the load-bearing word/element only.
7. **Honest content** — numbers are real and sourced; nothing implies a claim the human can't back.
8. **Voice** — the words sound like the human, not like marketing filler.
9. **Craft check** — no orphan words, no clipped descenders, no misaligned elements at 1:1 zoom.
10. **The gut line** — the human (or the critic standing in for them) would post this without wincing.

## Complaint log (this is where taste accumulates)

When the human critiques a render, append the complaint here as a testable rule, dated. Example format:

- `2026-01-15 — "the hand-drawn marks are on every slide, they stopped meaning anything" → marks must be earned; max 2–3 per asset; never the same mark twice.`
